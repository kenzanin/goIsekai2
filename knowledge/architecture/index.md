# Architecture
* [Event-driven core: domain events on gookit/event, stream plane separate](event-driven-core.md) - Two-plane event architecture: gookit/event managed by a single actor goroutine for domain facts after commit, plus a separate bounded drop-oldest stream hub for SSE; typed facade, event catalog, concurrency contract and gookit internals to defend against.
* [State machines: plugin and job lifecycle on qmuntal/stateless; cache entry and daemon deliberately not](state-machines.md) - Four entity lifecycles with explicit ownership: plugin and job use qmuntal/stateless with typed enums and external SQLite state, image cache entries use a typed enum plus singleflight, daemon uses an ordered slice; persist-before-publish, boot reconciliation, graph golden tests and cppIsekai divergences.
* [Architecture overview: layers, import rules and frozen external contracts](overview.md) - goIsekai2 shape as one local daemon: layer map and import matrix, model as the only shared package, store as the only SQL speaker, request paths for chapters and images, frozen baselines (routes, plugin ABI, status vocabulary, cache tree, config precedence), data directory and the open stack decisions.
* [Concurrency and ownership: one owner per mutable resource, bounded everything](concurrency-ownership.md) - Ownership table for config, SQLite, bus, stream hub, plugin registry and workers; MaxOpenConns(1) serialization with a non-nesting Tx helper; backpressure policy per path, timeout table from baseline values, shutdown ladder, forbidden patterns and race/leak gates.
* [Data flows: five ordered sequences and the invariants that keep them reproducible](data-flows.md) - Ordered flows for save, chapter open, image serve, config save and plugin toggle, each naming the commit point, the published event and the stream effect, plus an ordering review checklist and the rules that make each step idempotent or lossy.
* [Boot and shutdown: ordered startup, dependency-ordered teardown, and the test that proves both](boot-shutdown.md) - Fifteen-step boot order derived from cppIsekai main.cpp with failure modes, the ordering constraints behind it, the shutdown ladder (stop accepting, workers, scheduler, plugins, browser, log drain), deliberate divergences, and one integration test contract.
* [Image cache: v3 layout, namespace by display name, slug rules, LRU and pure-Go transcode](cache-layout.md) - Frozen v3 cache tree with plugin namespace derived from display name, slug and slug_dir rules with collision suffix, cover/page naming and id8 chapter suffix, extension-free hits with sidecars, placement-context requirement (no sha fallback), byte-based LRU and the pure-Go transcode knobs.
* [Capability map: 25 baseline specs collapsed into 11 V2 capabilities with a porting order](capability-map.md) - Maps the 25 cppIsekai capability specs onto 11 V2 capabilities (config, store, plugin-host, host-tools, library, reader, image-cache, detail, updates, browser, sites), with the V2 change per capability, porting rules and the dependency-ordered porting sequence.
