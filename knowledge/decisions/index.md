# Decisions
* [goIsekai2 is a greenfield Go rewrite against the cppIsekai baseline](goisekai-v2-bootstrap.md) - Decisions: cppIsekai is the read-only behavioral baseline (its knowledge bundle + openspec specs), goIsekai V1 is a read-only scraping corpus, bundles never merge, module goisekai2.
* [Adopt gookit/event behind a single-actor bus; separate stream plane](event-dispatch.md) - User ruling 2026-11-21: gookit/event v1.2.0 as dispatch engine, owned by one actor goroutine, async API banned, typed payload facade, drop-oldest stream hub delivered over WebSocket `GET /ws/log`; hand-written hub kept as documented fallback.
* [Use qmuntal/stateless as the FSM engine behind typed domain wrappers](state-machine-engine.md) - User ruling 2026-11-21: qmuntal/stateless v1.8.0 for plugin and job machines instead of a hand-written engine, with typed enums, single owner goroutine, SQLite external state (persist before publish) and graph golden tests; cache entries and daemon lifecycle excluded.
* [Dependency stack: pure Go only (modernc sqlite, tls-client, modernc lua, quickjs, wazero)](dependency-stack.md) - No-cgo constraint with CGO_ENABLED=0 as build gate; chosen modernc.org/sqlite v1.62.0, bogdanfinn/tls-client v1.18.1, modernc.org/lua v0.1.0 (Lua 5.5.1), modernc.org/quickjs v0.27.0 and tetratelabs/wazero v1.12.0; rejection of gopher-lua, buke/quickjs-go, wasm3 and the purego native-lib route.
* [Image transcode without libvips: gen2brain WASM-transpiled webp/avif/jxl, pure-Go resize](image-pipeline.md) - Replaces the baseline libvips pipeline with cgo-free gen2brain/webp, gen2brain/avif and gen2brain/jpegxl (libwebp/libavif/libjxl compiled to WASM and transpiled to Go), x/image draw for resize, nodynamic build tag for determinism, plus parity and benchmark gates.
* [chi + coder/websocket for HTTP and WebSocket](http-framework.md) - Use go-chi v5 as the HTTP router and coder/websocket for the log stream, keeping handlers on net/http so middleware and SSR stay stdlib-compatible.
* [Browser host transport and supervision in Go](browser-host-transport.md) - Keep the baseline browser-host tool surface; supervise lightpanda with os/exec and hide the transport behind one Browser interface.
* [chi + coder/websocket for HTTP and WebSocket](http-framework.md) - Use go-chi v5 as the HTTP router and coder/websocket for the log stream, keeping handlers on net/http so middleware and SSR stay stdlib-compatible.
* [Tray as a separate pure-Go command on fyne.io/systray](tray.md) - fyne.io/systray v1.11.0 in its own tray binary: pure Go on Linux (dbus StatusNotifierItem) and Windows, cgo only on macOS; the daemon itself stays pure Go and is spawned as a child.
* [INI config file handled by unknwon.dev/ini/v2](config-file-format.md) - Use unknwon.dev/ini/v2 v2.0.0-beta.7 for reading, merging and saving the goIsekai2 ini instead of a hand-written ordered document model or the v1 package; comments, key order and unknown keys survive, byte-identical formatting does not.
* [Store access: GORM with one raw-SQL boundary](store-access.md) - GORM runs on the pure-Go glebarez/sqlite driver; raw SQL is confined to the internal/store/sql module and enforced by scripts/sql-boundary-check.
* [No generic worker pool: job runners plus semaphores](concurrency-pool-policy.md) - goIsekai V2 does not build a general worker pool: only the scheduler has bounded job runners, while plugin calls and fetches use semaphores and SQLite serialization comes from database/sql.
* [UI stack: templ + Tailwind + Alpine + htmx](ui-stack.md) - goIsekai V2 SSR UI uses typed templ components, compiled Tailwind CSS, and locally vendored Alpine/htmx; generated assets are committed and embedded.
* [First site corpus tranche and parity tracking](site-corpus-scope.md) - Port seven baseline plugin folders first and record every other baseline folder as an omission with a reason rather than silently dropping it.
* [saved_manga is the single master for manga data](saved-manga-master-data.md) - All manga metadata lives in saved_manga; satellite tables are keyed by (plugin, slug) and never own competing title data. Detail API materializes it.
* [Explicit saved state on the saved_manga master row](saved-state-marker.md) - added_at is the saved marker: >0 means in library, 0 means materialized but unsaved. Viewing a title never saves it.
* [Lua runtime: modernc.org/lua v0.1.0 for Lua 5.5.1 plugins](lua-runtime.md) - GoIsekai2 Lua plugins run on modernc.org/lua v0.1.0 (PUC-Rio Lua 5.5.1 translated to pure Go by ccgo), replacing gopher-lua v1.1.2 so plugins can use Lua 5.5 syntax while CGO_ENABLED=0 remains the build gate.
* [Plugin io shim is read-only and confined to the plugin directory](confined-io-shim.md) - V2 exposes io.read and io.lines to plugins, but unlike cppIsekai the paths are confined to the calling plugin directory; absolute paths and .. escapes fail with typed errors.
* [Manga detail is a cache-only read path](cache-only-read-path.md) - Every field rendered on manga detail comes from the store; plugin and enrichment fetches happen only in explicit user actions or the update scheduler, never during GET rendering.
* [Staged plugin JSON lives in api_cache, not a separate in-memory DB](staging-json-in-api-cache.md) - The raw detail/chapters envelopes fetched from a search-result action are stored in the main SQLite api_cache table with a TTL; Save promotes them into saved_manga.
